## 实时动作

| 动作类型 | 用途 | 参数示例 |
| --- | --- | --- |
| `subtitle` | 播放 Announcer 字幕组。 | `group: welcome_demo` |
| `quest.offer` | 通过 QuestGPS 向玩家展示可接取任务。 | `quest: chapter_two`、`open-menu: true` |
| `quest.track` | 通过 QuestGPS 追踪已接取任务。 | `quest: chapter_two` |
| `message` | 向玩家发送聊天栏提示。 | `text: "已解锁下一阶段"` |
| `command` | 以控制台或玩家身份执行固定命令。 | `executor: console`、`command: save-all` |

字幕动作需要 Announcer，任务动作需要 QuestGPS。消息、字幕组和任务 ID 可引用 `{quest_id}` 等事件字段。命令使用固定参数，`executor` 可设为 `console` 或 `player`。以玩家身份执行时，该玩家须在线并完成进服验证。

## 副本通关邮件

单服可用 SQLite 处理本服副本通关结果。通过共享 MySQL 处理跨服副本结果时，EventPacket 需要当前服务器的有效客户水印席位，EventPacket、Abyss 和 Mail 须使用同一套宿主共享 MySQL。 [客户水印包](/docs/guide/module-delivery#安装客户水印包)

```yaml
rules:
  abyss-clear:
    enabled: false
    trigger: abyss-result
    when:
      dungeon: example_dungeon
      difficulty: hard
      outcome: COMPLETED
    actions:
      - type: mail
        id: clear-reward
        title: "副本通关奖励"
        content: "你已通关 {dungeon}，难度 {difficulty}。"
        currency: money
        amount: 100
```

填写实际的副本、难度和货币 ID，并启用 Abyss 与 Mail。纯通知可省略 `currency` 和 `amount`。保持规则与邮件动作 `id` 稳定，避免重复发奖。省略 `start-sequence` 时，从启用规则后的结果开始处理。用 `/axs eventpacket status` 检查持久规则状态。

## 用信号播放字幕

先在 Announcer 配置[字幕组](/docs/announcer/subtitle#字幕组文件格式) `welcome_demo`，再将规则合并到 EventPacket 主配置的 `rules`。

```yaml
rules:
  welcome-notice:
    trigger: signal
    signal: welcome_demo
    actions:
      - type: subtitle
        group: welcome_demo
```

执行 `axs reload eventpacket`，再执行 `axs eventpacket fire welcome_demo WikiTester`，把 `WikiTester` 换成已通过准入的在线测试玩家。确认字幕播放后，按[按钮发送信号](/docs/menu/actions#按钮发送信号)接入 Menu。

## 首次准入邮件

启用 LoginView、Mail 和 EventPacket，将规则合并到 `rules`。

```yaml
rules:
  welcome-mail:
    trigger: first-admitted
    actions:
      - type: mail
        id: welcome
        title: "欢迎加入服务器"
        content: "你的冒险从这里开始。"
```

重载 EventPacket，让尚未通过准入的测试账号完成首次进服验证，再打开收件箱确认欢迎邮件。用同一账号重新进服，核对没有新增同一封邮件。
