## 实时动作

| 动作类型 | 用途 | 参数示例 |
| --- | --- | --- |
| `subtitle` | 播放 Announcer 字幕组。 | `group: welcome_demo` |
| `quest.offer` | 通过 QuestGPS 向玩家展示可接取任务。 | `quest: chapter_two`、`open-menu: true` |
| `quest.track` | 通过 QuestGPS 追踪已接取任务。 | `quest: chapter_two` |
| `quest.accept` | 通过 QuestGPS 接取指定任务。 | `quest: chapter_two` |
| `quest.open` | 打开 QuestGPS 任务菜单。 | `- { type: quest.open }` |
| `message` | 向玩家发送聊天栏提示。 | `text: "已解锁下一阶段"` |
| `command` | 以控制台或玩家身份执行固定命令。 | `executor: console`、`command: save-all` |
| `ui.packet` | 给本服符合接收范围的玩家发送 ArcartX 界面数据。 | `ui: "AXS:example"`、`handler: update`、`audience: self`、`data: { stage: "{quest_id}" }` |
| `chat.card` | 给触发者发送已定义的聊天卡片。 | `card: welcome`、`data: { message: "欢迎" }` |
| `title.give` | 通过 Title 授予称号。 | `title: veteran`、`duration: 7d` |
| `combat-effect.play` | 通过 CombatEffect 播放已注册的效果包。 | `effect: kill-effect`、`data: { caption: "已完成" }` |
| `qq.message` | 通过 QQBot 向已配置的群发送文本。 | `group: 123456` 或 `group: all`，以及 `text: "活动已开启"` |
| `mail.send` | 用 Mail 异步发送一封实时通知。 | `title: "提示"`、`content: "已完成 {quest_id}"` |
| `mail.preset` | 用 Mail 异步发送已配置的邮件预设，预设可带附件。 | `preset: chapter_reward` |

字幕动作需要 Announcer，任务动作需要 QuestGPS。消息、字幕组和任务 ID 可引用 `{quest_id}` 等事件字段。命令使用固定参数，`executor` 可设为 `console` 或 `player`。以玩家身份执行时，该玩家须在线并完成进服验证。

发 UI 包、聊天卡片和战斗特效时，`data` 可配置至多 16 个字符串字段，字段值支持事件模板。客户端只提交选中的规则 ID，动作、目标和命令由服务端配置决定。

`ui.packet` 的 `audience` 可设为 `self`、`all-online` 或 `others`。`self` 是默认值，直接发送给触发者。`all-online` 包含触发者及本服其他已通过准入的在线玩家，`others` 排除触发者。后两种范围在开始分发时记录在线会话，按 tick 小批发送，离线或已更换会话的玩家会被跳过。触发者会话失效、规则重载或模块停用时，取消该波尚未发送的包。

实时邮件进入 Mail 的异步提交，EventPacket 同时最多提交 64 封尚未完成的实时邮件。重启可恢复的发奖继续使用副本、首次准入或拍卖成交持久规则。

## 副本通关邮件

单服可用 SQLite 处理本服副本通关结果。通过共享 MySQL 处理跨服副本结果时，EventPacket 需要当前服务器的有效客户水印席位，EventPacket、Abyss 和 Mail 须使用同一套宿主共享 MySQL。

在 `rules/mail.yml` 中配置副本通关邮件。

```yaml
rules:
  abyss-clear:
    enabled: false
    trigger: abyss-result
    when:
      dungeon: example_dungeon
      difficulty: hard
      outcome: COMPLETED
    actions:
      - type: mail
        id: clear-reward
        title: "副本通关奖励"
        content: "你已通关 {dungeon}，难度 {difficulty}。"
        currency: money
        amount: 100
```

填写实际的副本、难度和货币 ID，并启用 Abyss 与 Mail。纯通知可省略 `currency` 和 `amount`。保持规则与邮件动作 `id` 稳定，避免重复发奖。省略 `start-sequence` 时，从启用规则后的结果开始处理。用 `/axs eventpacket status` 检查持久规则状态。

## 用信号播放字幕

先在 Announcer 配置[字幕组](/docs/announcer/subtitle#字幕组文件格式) `welcome_demo`，再将规则合并到 `rules/events.yml`。

```yaml
rules:
  welcome-notice:
    trigger: signal
    signal: welcome_demo
    actions:
      - type: subtitle
        group: welcome_demo
```

执行 `axs reload eventpacket`，再执行 `axs eventpacket fire welcome_demo WikiTester`，把 `WikiTester` 换成已通过准入的在线测试玩家。确认字幕播放后，按[按钮发送信号](/docs/menu/actions#按钮发送信号)接入 Menu。

## 首次准入邮件

启用 LoginView、Mail 和 EventPacket，将规则合并到 `rules/mail.yml`。

```yaml
rules:
  welcome-mail:
    trigger: first-admitted
    actions:
      - type: mail
        id: welcome
        title: "欢迎加入服务器"
        content: "你的冒险从这里开始。"
```

重载 EventPacket，让尚未通过准入的测试账号完成首次进服验证，再打开收件箱确认欢迎邮件。用同一账号重新进服，核对没有新增同一封邮件。
