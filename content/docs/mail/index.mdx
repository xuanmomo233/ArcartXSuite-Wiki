| 模块 ID | `mail` |

| 主要调整内容 | presets/ 邮件预设、附件、有效期与清理设置 |
| 重载 | `/axs reload mail` |

## 开始前

确认 ArcartX 客户端可用，且 `/axs status` 显示本模块已加载。本模块还需要安装 `PlaceholderAPI`。可选插件只在使用对应功能时安装，具体要求见功能配置页。

## 第一次使用

1. 编辑一个默认预设。
2. 按命令页向测试玩家发送。
3. 执行 `/mail` 打开收件箱。

## 检查是否配置成功

阅读邮件并领取附件，确认物品或货币到账。

预设修改后，用 `/axs mail preset send trial_supply WikiTester` 向在线测试玩家派发一封新邮件。收件箱找不到邮件时核对预设 ID 和收件人。已经收到却没有附件时，核对[预设的附件字段和领取步骤](/docs/mail/presets#先验证预设派发与附件领取)。

## 玩家寄信结果待核对

写信时加入的附件会单独保管。提交前关闭写信界面或离服时，物品会尝试放回背包。异常重启后，请回到原游戏服打开写信界面。确认尚未开始退回的附件会继续归还，退回结果不明的附件会保留待核对。若背包空间不足，腾出空间后再试。若提示附件待核对，请联系管理员检查原服的附件记录和背包存档。重新写信时，需要填写收件人、标题和正文。

增减附件或打开写信界面时，请等后台核对完成。背包或会话在等待期间发生变化时，本次尚未执行的附件操作会取消，可按界面提示重试。

寄信前会确认物品附件已从发件人背包存档扣除。所有需要扣款的寄信都会在扣款前保存凭证，包括没有物品附件的邮件。收到「扣款待核对」时，请把凭证编号交给管理员核对经济流水，附件也会保留至核对完成。收到「寄信结果待核对」时，可在原游戏服重新打开写信界面查询原凭证。

寄信请求受理后，请等待发送结果。确认寄出后，收件人可以在收件箱查看邮件。收费寄信或携带物品附件的寄信在重启后会按原凭证核对。确认未寄出时，尚未启动的退款会尝试退回已确认扣除的费用，确认未退回的附件会归还背包。若空间不足，请腾出空间后重新打开写信界面取回。退款或附件退回结果待核对时，请保留凭证编号并联系管理员。

关闭界面或离服时，待核对的附件会继续保留。若结果持续待核对、游戏服已重启，或收到退款待核对提示，请将凭证编号交给管理员。管理员可在 `plugins/ArcartX-Suite/data/mail/send-review/` 查找对应资料，核对收件记录与经济流水。处理物品附件前，还需核对发件人的背包存档。

## 可以配置的功能

| 特性 | 说明 |
|---|---|
| 收件箱系统 | ArcartX UI 驱动的收件箱界面，支持分页浏览、来源筛选、预览、领取和删除 |
| 玩家写信 | 玩家可向其他玩家发送邮件，支持物品附件和 Vault 货币附件，含手续费与税率 |
| 预设邮件 | 管理员预设邮件模板，支持批量派发给在线玩家或全部注册玩家，含二次确认机制 |
| 物品附件 | 支持原版、MythicMobs、NeigeItems、Overture、MMOItems 物品库产物，含 Base64 完整序列化 |
| 货币附件 | 支持 Vault 金币和多货币系统附件，货币附件可自定义展示图标 |
| 领取条件 | 预设邮件支持 `claim-conditions` 领取条件，使用 ScriptCondition 引擎（PAPI/Aria/JS） |
| 领取命令 | 预设邮件支持 `claim-commands` 领取时执行命令，支持 `{player}` 等变量 |
| 内容审核 | 敏感词、正则、物品材质、Lore 正则、物品名称正则、NBT/PDC 键值屏蔽 |
| 跨服广播 | 多服邮件刷新通知（Redis + Proxy 双后端），收件人上线自动刷新收件箱 |
