description: "配置快捷道具的即时效果、药水和分组属性加成，包括 TaCZ 模组属性。"
---

每个道具定义都需包含一个 `effects` 配置节。在里面按字段填写即时效果、药水和属性。药水和属性组各自设置 `duration`，单位为秒。若重载日志提示 `effects 必须为配置节`，请检查 `effects` 是否按下面的 YAML 结构填写。

## 即时效果

```yaml
effects:
  health:
    points: 4
    max-health-percent: 10
  food: 2
  experience: 5
  messages:
    - "&a{player} 已获得补给。"
  commands:
    - "say {player} 使用了补给"
```

| 字段 | 值 |
|------|----|
| `health.points` | 固定生命值。2 点等于 1 颗心，计算后的生命值限制在 0 到最大生命值 |
| `health.max-health-percent` | 按最大生命值百分比计算。10 表示 10%，可和 `points` 相加 |
| `food` | 改变饱食度，结果限制在 0 到 20 |
| `experience` | 增加经验点数，使用非负整数 |
| `commands` | 按顺序派发的控制台命令列表。用 `{player}` 代入玩家名，例如 `"give {player} minecraft:bread 1"` |
| `messages` | 玩家消息列表。支持 `{player}` 和 `&` 颜色码 |

一次使用先检查能否使用及属性数值，确认后处理物品消耗和冷却。即时效果依次处理生命值、饱食度、经验、药水、命令和消息，临时属性最后施加。只填写道具用到的字段即可。

## 药水

```yaml
effects:
  potions:
    - id: minecraft:speed
      level: 2
      duration: 15
      particles: false
    - id: minecraft:regeneration
      level: 1
      duration: 5
      icon: false
```

| 字段 | 值 |
|------|----|
| `id` | 命名空间药水效果 ID |
| `level` | 显示等级，1 至 256，默认 1 |
| `duration` | 持续秒数，至少 1 秒 |
| `ambient` | 是否使用环境效果显示，默认 `false` |
| `particles` | 是否显示粒子，默认 `true` |
| `icon` | 是否显示图标，默认 `true` |

## 属性组

在 `effects.attributes` 下填写提供方和自定义组名。每组配置自己的持续秒数及属性修饰器。同一组内每个属性 ID 写一次。要给同一属性配置两种运算或不同持续时间，可以把它分别放在两个组里。

| 提供方 | 配置方式 |
|--------|----------|
| `mod` | `modifiers` 列表，填写模组注册的命名空间属性 ID。需开启本体 `mod-attributes.enabled`，并使用支持该桥接的 Forge 混合端 |
| `symphony` | `modifiers` 列表，填写 Symphony 中已定义的命名空间属性 ID |
| `mythiclib` | `modifiers` 列表，填写 MythicLib 属性 ID，如 `ATTACK_DAMAGE`。支持加算 |
| `attributeplus` | `lines` 列表，填写 AttributePlus 能读取的词条 |
| `craneattribute` | `lines` 列表，填写 CraneAttribute 能读取的词条 |

对接属性插件时，在 Suite 本体 `config.yml` 的 `attribute-bridges` 下启用同名开关，再用 `/axs prop status` 查询桥接状态。一份道具使用多个提供方时，每个提供方都需要可用。每个组的 `duration` 必须为正整数，并且至少包含一条 `modifiers` 或 `lines`。

### 修饰器字段

每条修饰器指定 `id`、`amount` 和可选的 `operation`。Forge 模组属性和 Symphony 支持以下运算。

| 运算 | 含义 |
|------|------|
| `add` | 默认值，直接加上 `amount` |
| `multiply-base` | 按基础值乘以 `amount` 计算加成 |
| `multiply-total` | 总值乘以 `1 + amount` |

倍率填写比例，例如 `0.2` 表示 20%。属性数值的单位和实际计算顺序由对应提供方定义。

### 用 Aria、Symphony 属性与 PAPI 计算数值

`modifiers[].amount` 可以填数字，也可以直接填一行 Aria 公式。比如将玩家当前 Symphony 物理伤害的 20% 转成枪械弹片伤害，最多提高 20 点。

```yaml
- id: gunsmithlib:bullet_damage
  operation: add
  amount: "math.min(20, global.stats.symphony('physical_damage') * 0.2)"
```

`global.stats.symphony('physical_damage')` 读取玩家当前结算后的属性。省略命名空间时使用 `symphony:`，自定义命名空间请传完整 ID。 [Symphony 属性 API](https://wiki.arcartx.com/docs/symphony/29_attribute_api)

`global.stats.papi('%player_world_time%')` 读取数值型占位符，`global.level` 是玩家的原版经验等级。两者都可以直接参与计算。PAPI 需要对应扩展，返回值必须是数字。 [PlaceholderAPI Player 扩展](https://github.com/PlaceholderAPI/Player-Expansion/blob/master/src/main/java/com/extendedclip/papi/expansion/player/PlayerExpansion.java)

```yaml
amount: "5 + global.level * 0.2 + global.stats.papi('%player_world_time%') / 24000"
```

较长的公式可以用 YAML 的 `>-` 换行。需要给输入取别名时，可将 `amount` 写成带 `aria` 字段的配置节，在 `papi` 或 `symphony` 下映射变量名，公式里用 `global.<变量名>` 读取。`level` 和 `stats` 是内置变量名。

```yaml
amount:
  aria: "math.min(20, global.power * 0.2 + global.xp_level * 0.5)"
  symphony:
    power: symphony:physical_damage
  papi:
    xp_level: "%player_level%"
```

别名由英文字母、数字和下划线组成，首字符使用字母或下划线。`papi` 和 `symphony` 中的别名应各不相同。`symphony` 映射中的属性填完整命名空间 ID。

同次使用的公式在消耗与施加前按当前 Symphony 属性统一计算，包含仍生效的道具效果。再次使用会按当时属性重算，每次计算值维持至该效果结束。

依赖不可用、属性缺失、占位符解析失败或公式未返回有限数值时，本次使用会被取消。开启 `settings.debug` 可在控制台查看出错的属性组和字段。

### TaCZ 强化剂

#### Symphony 为什么会覆盖枪械伤害

`gunsmithlib:bullet_damage` 影响 TaCZ 命中。启用 Symphony 战斗接管后，符合接管条件的伤害会按配置通道重新结算。默认物理通道读取 `symphony:physical_damage`。例如，该通道以 20 点物理攻击作为输入时，枪械伤害从 7 提至 12 的差额不会计入该次结算。 [Symphony 伤害结算](https://wiki.arcartx.com/docs/symphony/15_damage_pipeline)

接管取决于具体命中和实体拥有的属性来源。装备、状态或外部插件登记的修饰器都可能成为来源。仅受击者拥有 Symphony 来源时，Symphony 可以读取事件原伤害作为输入，再计算防御、格挡和护盾。

#### 由 TaCZ 结算枪械伤害

使用 `effects.attributes.mod` 写入 GunsmithLib 注册在玩家实体上的枪械属性。以下道具增加 15 秒弹片伤害和 8 秒换弹速度。 [GunsmithLib 属性文档](https://github.com/ChloePrime/GunsmithLib/blob/c5a0180a87d21def1f446c04b81c487aad71969c/src/main/resources/docs/attributes.md)

```yaml
name: "枪械强化剂"
coolDownGroup: "枪械增益"
coolDownTime: 45
effects:
  attributes:
    mod:
      gun-damage:
        duration: 15
        modifiers:
          - id: gunsmithlib:bullet_damage
            amount: 5
      fast-reload:
        duration: 8
        modifiers:
          - id: gunsmithlib:reload_speed
            amount: 0.2
            operation: multiply-total
```

也可以把弹片伤害的 `amount` 写成单行公式，按当前 Symphony 物理攻击和 PAPI 原版经验等级计算。此例需要 PlaceholderAPI 的 Player 扩展。

```yaml
amount: "global.stats.symphony('physical_damage') * 0.2 + global.stats.papi('%player_level%') * 0.5"
```

若希望由 TaCZ 结算枪械伤害，可以在 `plugins/Symphony/config.yml` 中将 `combat.enabled` 设为 `false` 后重启。这个开关会关闭 Symphony 的战斗结算，Prop 仍可读取 Symphony 属性参与公式。 [Symphony 配置参考](https://wiki.arcartx.com/docs/symphony/26_config_reference)

#### 由 Symphony 接管伤害

使用 `effects.attributes.symphony` 给实际参与结算的通道加属性。下面按默认物理通道配置，临时增加 5 点物理攻击。结算时，这 5 点作为物理通道输入的一部分，继续受目标的物防、格挡和护盾影响。

```yaml
name: "力量强化剂"
coolDownGroup: "物理增益"
coolDownTime: 45
effects:
  attributes:
    symphony:
      physical-boost:
        duration: 45
        modifiers:
          - id: symphony:physical_damage
            operation: add
            amount: 5
```

自定义伤害通道时，在 Symphony 的 `damage/*.yml` 查找 `damage-attribute`，将 `id` 填为其完整属性 ID。加成适用于读取该属性的攻击，包括近战。若只增强 TaCZ 并保留 Symphony 的减伤和护盾，需要为 TaCZ 命中使用枪械伤害输入。

### 自定义 Symphony 属性和插件词条

下面的 `server:focus` 是示例 ID，请替换为 Symphony 配置中定义的属性。AttributePlus、CraneAttribute 的词条名称按对应插件的服务器配置填写。只有启用了所用的提供方，这份道具才可使用。

```yaml
effects:
  attributes:
    symphony:
      focus:
        duration: 12
        modifiers:
          - id: server:focus
            amount: 3
    mythiclib:
      attack:
        duration: 10
        modifiers:
          - id: ATTACK_DAMAGE
            amount: 5
    attributeplus:
      strength:
        duration: 10
        lines: ["物理伤害:10"]
    craneattribute:
      defense:
        duration: 6
        lines: ["防御:5"]
```

## 时长与重复使用

药水与各组属性可以使用不同的 `duration`，例如 10 秒药水与 30 秒属性。再次使用会重新计算和计时。允许提前刷新时，将冷却设为短于效果时长。

到期、死亡、退出、模块重载或停用时会清除对应的 Prop 临时属性。不同道具、不同组及称号的属性来源独立计时。药水交由原版药水规则处理，命令、发消息、增加经验和已恢复的生命值在使用时生效。

## 使用事件联动

成功使用道具会发布 `axs.prop.prop_used`。BattlePass 的「道具专家」任务已订阅，EventPacket 可以用 `event-bus` 触发器监听。事件携带以下文本字段。

| 字段 | 值 |
|------|----|
| `prop_id` | 道具定义 ID |
| `trigger` | 手持为 `hand`，按键为 `key`，自动触发为 `auto` |
| `consumed` | 是否消耗物品，`true` 或 `false` |
| `cooldown_group` | 道具冷却组 |
| `max_duration_seconds` | 药水和属性组中最长的持续秒数。纯即时效果为 `0` |

### BattlePass 只统计指定道具的消耗

按[战令任务示例](/docs/battlepass/tasks#任务配置示例)创建一条测试任务，将原来的 `bukkit-event` 和 `conditions` 换成下列字段。示例统计 [`field_ration` 补给](/docs/prop#第一次使用)实际消耗的次数；若只统计一种使用入口，再按 `trigger` 添加条件。

```yaml
event-topic: "axs.prop.prop_used"
conditions:
  - type: event_payload
    key: prop_id
    operator: equals
    value: "field_ration"
  - type: event_payload
    key: consumed
    operator: equals
    value: "true"
```

用已经领取该任务且饱食度未满的玩家右键使用一份补给，检查物品减少一个、任务进度增加 1。

### EventPacket 按道具使用触发动作

先按[自动触发教程](/docs/prop/keybinds#自动触发)配置 `first_aid`。将规则加入 EventPacket 主配置 `data/eventpacket/config.yml` 的 `rules` 并重载。示例在玩家自动使用急救包后发送消息。

```yaml
rules:
  first-aid-used:
    enabled: true
    trigger: event-bus
    topic: axs.prop.prop_used
    when:
      prop_id: "first_aid"
      trigger: "auto"
      consumed: "true"
    actions:
      - type: message
        text: "&a已自动消耗一份急救包。"
```

把急救包放入已绑定的额外槽位，并在测试服将玩家生命降到 8 点或以下。成功自动使用后应恢复生命、消耗一个急救包并显示消息。身上没有急救包或生命高于阈值时不应触发。

## 排错

| 现象 | 检查位置 |
|------|----------|
| 重载后找不到道具 ID | 查看重载日志中的文件路径和字段。确认 `effects` 为配置节，同一 ID 只对应一个定义 |
| 提示依赖的提供方不可用 | 用 `/axs prop status` 检查对应桥接，再核对插件安装、Suite 本体开关和模组环境 |
| 提示当前角色属性不可用 | Forge 属性要挂载在目标玩家实体上，MythicLib 属性要先在对应插件中注册 |
| 提示属性数值无法计算 | 核对 Aria 表达式、Symphony 属性 ID 和 PAPI 展开结果。打开 `settings.debug` 查看对应属性字段 |
| 显示有枪械属性加成，实际掉血未变化 | 检查 [Symphony 是否接管枪械伤害](#symphony-为什么会覆盖枪械伤害) |
| 无法确认道具槽位已更新 | 检查 ArcartX 额外槽位的实际内容、ID 与更新脚本，再尝试使用 |

桥接、属性或数值计算未通过时，本次使用在消耗物品和启动冷却前中止。自动触发会静默跳过，可以临时启用同一道具的主手或按键入口查看对应提示。
