---
title: "世界规则"
description: "配置整个世界的默认旗标，并为局部区域设置飞行、交互、传送、拾取和聊天例外。"
---

打开 `/rg admin`，选择左侧「世界」和目标世界，即可编辑整世界的默认旗标。「规则开关」与区域使用同一套允许、禁止和继承操作，保存后在 `regions.yml` 中形成 `type: global` 记录。

`global` 默认 ID 是 `__global__`。局部区域和其父区没有提供规则时，才使用对应世界的默认值。所有位置均未配置该旗标时，Regions 返回默认状态。

## 禁飞世界中的局部飞行区

```text
/rg worlddefault world
/rg flag world:__global__ fly deny
/rg flag world:arena fly allow
```

该示例要求 `arena` 已存在。世界默认禁飞，`arena` 中允许玩家使用已有的飞行能力。`fly` 允许规则用于保护判定，飞行能力本身由游戏模式或提供飞行的功能授予。

开启飞行、进入禁飞位置或保存影响飞行的规则后，模块会检查飞行状态。具有 `axs.regions.bypass` 的玩家可绕过飞行限制。

## 活塞与爆炸保护

```text
/rg flag world:__global__ pistons deny
/rg flag world:workshop pistons allow
/rg flag world:__global__ tnt deny
/rg flag world:__global__ creeper-explosion deny
/rg flag world:__global__ other-explosion deny
```

活塞会检查活塞本身、前方以及每个被移动方块的起点和终点。移动路径上有位置被禁止时，整次伸出或收回会取消。

爆炸规则按每个受影响方块的位置判断，保护被禁止区域的方块。玩家所受伤害由伤害相关旗标另外处理。

## 方块交互与材质列表

在「世界」中进入「交互限制」，填写 Bukkit 方块材质名，加入禁用列表。例如铁砧使用 `ANVIL`，末影箱使用 `ENDER_CHEST`。对应文件内容如下。

```yaml
version: 2
regions:
  - id: __global__
    world: world
    type: global
    blocked-interactions: [ANVIL, ENDER_CHEST]
    flags:
      use: true
```

这个配置允许其他普通交互，禁用列出的两种方块。某个管理区域明确设置 `use: true` 时，可以覆盖普通交互的世界默认限制。

交互按局部规则、世界默认两层判断。每层中，重生锚先检查 `respawn-anchors`，其余普通交互检查 `use`；普通世界交互还先检查材质禁用列表。容器操作另需通过 `chest-access`。用 `use: false` 限制访客时，适用规则的成员可享受成员豁免。

## 传送与出入边界

```text
/rg flag world:__global__ teleport deny
/rg flag world:__global__ enderpearl allow
/rg flag world:spawn entry allow
```

该示例默认禁止普通传送，并为末影珍珠设置允许规则。一次传送按起点和终点分别判断，每一端先查局部旗标，再取世界默认值。末影珍珠和紫颂果在各层先查 `enderpearl`、`chorus-fruit`，缺省时查 `teleport`。

跨越边界还需满足目的地的 `entry` 和出发地的 `exit`。例如局部允许珍珠传送，但目的地 `entry: false`，跨入仍会被拒绝。行走和传送门同样检查边界出入。

## 禁止拾取物品

```text
/rg flag world:__global__ item-pickup deny
```

拾取时同时检查玩家与掉落物所在位置。规则适用于贴近物品时的自动拾取、Pickup 菜单点击收取、快捷键收取和一键全收。

被禁止的物品会留在地面。拾取操作可分批处理，某一实体收取时会按当时的位置与规则重新检查。若规则来源区域设置了成员，成员豁免和 `axs.regions.bypass` 按同一套规则生效。

## 禁发与禁收公共聊天

```text
/rg flag world:quiet_zone send-chat deny
/rg flag world:quiet_zone receive-chat deny
```

`send-chat` 按发送者当前位置判断能否发送，`receive-chat` 按每个接收者当前位置过滤。Suite Chat 和原版公共聊天事件会使用这些规则。

接入自定义公共聊天的插件可调用[区域聊天判定接口](/docs/api/RegionChatAccess)，按发送者与各接收者分别检查。具体发送方式也决定私聊、公告和系统消息的处理范围。

## 查清实际结果

在目标位置打开 `/rg menu` 的「当前位置」，查看生效规则及来源。管理员用 `/rg why fly Alex` 查询 Alex 当前所在位置的飞行判定。

检查跨边界行为时同时核对起点和终点，检查交互时核对目标方块及 `use`、`chest-access` 或专用旗标。完整[旗标参考](/docs/regions/flags#旗标参考)与[文件字段](/docs/regions/configuration#区域与世界数据)可用于对照。
