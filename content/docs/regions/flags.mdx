旗标可设置在有界区域或世界默认记录上。管理员在面板中点「允许」「禁止」设置覆盖，点「继承」清除覆盖。

## 状态与写法

| 含义 | 面板 | 命令状态 | regions.yml |
| --- | --- | --- | --- |
| 明确允许 | 允许 | `allow`，也接受 `true`、`yes` | `true` |
| 明确禁止 | 禁止 | `deny`，也接受 `false`、`no` | `false` |
| 清除直接设置 | 继承 | `none` 或 `removeflag` | 删除这一项旗标 |

大部分旗标在禁止时阻止对应行为。`invincibility` 则在允许时启用无敌，`notify-enter` 和 `notify-exit` 在允许时向成员发送进出通知。`greeting` 和 `farewell` 可启用自定义文字。

## 重叠区域如何判定

每项旗标分别计算结果。

1. 先判断命中的管理区域 `managed`，再判断玩家领地 `claim`。
2. 同一类型按优先级从高到低查找，当前区域未设置时查询其父区。
3. 找到有效规则的层级后，同类型、同优先级的禁止结果优先。没有提供这项规则的高优先级区域会继续向后查找。
4. 局部区域没有给出结果时，使用所在世界的 `global` 默认旗标。
5. 所有来源均未设置时返回默认状态，Regions 对该旗标没有额外限制。

例如两个同级重叠区域分别设置 `pvp: true` 和 `pvp: false`，最终禁止玩家间伤害。管理区域设置的规则优先于玩家领地，单独提高领地优先级无法覆盖管理区域。

玩家的成员豁免在规则判定中计算。若另一个同级重叠区域仍给出禁止结果，该项行为仍可能被拒绝。玩家菜单的「当前位置」显示合并后的结果及来源。

## 父区域与世界默认值

父区必须位于同一世界，且不能形成继承环。

| 子区域类型 | 可设置的父区域 |
| --- | --- |
| `managed` 管理区域 | 管理区域或世界默认记录 |
| `claim` 玩家领地 | 世界默认记录 |
| `global` 世界默认记录 | 没有父区 |

父区按 ID 引用，是否提供继承值取决于父区的配置。世界默认值同时作为没有局部结果时的回退规则。

```text
/rg worlddefault world
/rg flag world:__global__ pvp deny
/rg parent world:shop world:town
/rg flag world:town block-break deny
/rg removeflag world:shop block-break
```

这里要求 `shop` 和 `town` 均为已存在的管理区域。`shop` 的破坏规则继承 `town`；如果整条父链都未设置某项规则，再取世界默认值。

## 成员与管理权限

成员包括直接列出的玩家 UUID、所有者，以及通过 `axs.regions.group.<组名>` 识别的成员组和所有者组。成员豁免以**实际提供规则的区域**为准，继承父区的禁止规则时核对父区成员。

| 范围 | 旗标 |
| --- | --- |
| 成员自动豁免 | `block-break`、`block-place`、`use`、`chest-access`、`vehicle-destroy`、`item-drop`、`item-pickup`、`ride`、`sleep` |
| 普通领地所有者额外可编辑 | `vehicle-place`、`damage-animals`、`greeting`、`farewell`、`notify-enter`、`notify-exit` |

普通领地所有者可以编辑上述两行列出的旗标，并管理领地成员。其他旗标需要 `axs.regions.admin`。可编辑某项旗标与享受成员豁免分别按表中范围判断。

## 绕过权限

`axs.regions.bypass` 适用于以下玩家操作旗标。

- 战斗和建造中的 `pvp`、`damage-animals`、`block-break`、`block-place`、`use`、`chest-access`、`trample`、`vehicle-destroy`。
- 玩家操作中的 `entry`、`exit`、`teleport`、`enderpearl`、`chorus-fruit`、`item-drop`、`item-pickup`、`fly`、`ride`、`sleep`、`respawn-anchors`。
- 公共聊天中的 `send-chat`、`receive-chat`。

活塞、爆炸、生成、生长等按环境位置处理的规则继续生效。伤害减免、饥饿、自然恢复及无敌等效果按对应旗标配置处理。

## 自定义进出文字

```text
/rg flag world:spawn greeting allow &6欢迎来到出生点！
/rg flag world:spawn farewell allow &7你已离开出生点。
```

也可以在管理面板的「消息」类别中点击「文字」。数据文件使用以下写法。

```yaml
flags:
  greeting:
    state: true
    text: "&6欢迎来到出生点！"
  farewell:
    state: true
    text: "&7你已离开出生点。"
```

设为禁止可关闭对应进出提示，清除覆盖则回到继承或默认值。文字显示位置由[通知设置](/docs/regions/configuration#通用设置)控制。

## 多个条件共同检查

传送需通过起点、终点和跨区边界规则，容器操作需通过交互及容器访问规则，拾取需通过玩家和掉落物两处规则。具体场景见[世界规则](/docs/regions/world-rules)。

玩家可在「当前位置」查看当前玩家脚下的生效结果，`/rg why <旗标>` 用于查询一项规则及其来源。登录和死亡重生使用各自的出生流程，环境事件则按受影响方块或实体的位置判断。
