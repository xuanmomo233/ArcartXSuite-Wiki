## 使用管理面板

执行 `/rg admin`，需要 `axs.regions.admin` 和可用的 ArcartX 客户端。

| 页面或按钮 | 操作 |
| --- | --- |
| 左侧「区域」 | 按页浏览有界区域，选择后加载该区域的详情 |
| 左侧「世界」 | 浏览已加载世界及已有区域记录所属世界，编辑世界默认规则 |
| 「新建区域」 | 输入名称，用当前选区创建管理区域，可先「检查选区」 |
| 「规则开关」 | 按战斗、方块、环境、生物、玩家、消息分类编辑 |
| 「允许」「禁止」 | 显式设置对应旗标 |
| 「继承」 | 清除该项直接设置，回到父区或世界默认判定 |
| 消息规则旁的「文字」 | 编辑进入或离开的自定义提示 |
| 「成员管理」 | 添加玩家、UUID 或 `g:权限组`，按页查看及移除成员或所有者 |
| 「区域设置」 | 重命名、设置优先级与父区、检查或采用当前选区、确认删除 |
| 世界的「交互限制」 | 加入或解除特定方块材质的禁交互限制 |

修改后等待「已保存」反馈。父区域输入留空可清除父区，删除区域需要再点「确认删除」。有子区域时先调整子区域的父区。

成员列表显示登录名或已保存的离线名称。未知成员可悬停查看 UUID，玩家改名后仍保持成员关系。

## 查看当前位置与我的区域

执行 `/rg menu` 打开玩家菜单。

| 页面 | 显示内容 |
| --- | --- |
| 「当前位置」 | 当前玩家脚下合并后的生效规则，来源可为具体区域、世界默认、成员豁免或权限绕过 |
| 「我的区域」 | 自己拥有或参与的区域，含权限组身份，支持翻页 |
| 参与区域的详情 | 该区域设置及继承值，便于核对配置 |
| 「我的选区」 | 世界、两个角点、体积，提供刷新和清除 |

管理员面板与参与区域详情用于编辑、查看区域本身的设置。要判断自己在重叠位置会受到什么保护，查看「当前位置」。交互、拾取和传送还会检查目标位置或材质。

## 用模板创建或更新区域

| 内置模板 | 适用场景 |
| --- | --- |
| `spawn` | 管理员出生点，限制建造、容器访问、玩家伤害、怪物生成、常见爆炸及活塞 |
| `public` | 公共设施，允许普通交互，限制建造和容器访问 |
| `claim` | 玩家领地，限制访客建造、交互、容器访问和伤害动物 |
| `arena` | 竞技场，允许玩家间伤害，限制建造和部分爆炸 |

```text
/rg template list
/rg template show spawn
/rg define spawn spawn
/rg template apply public world:town_hall
```

模板只改动列出的旗标。含管理员专属旗标的模板需要管理员权限，普通领地所有者可使用 `claim` 等可编辑范围内的模板。自定义写法见[区域模板](/docs/regions/configuration#区域模板)。

## 检查重叠与判定来源

创建前用 `/rg preview` 检查选区；调整已有区域时用 `/rg preview world:spawn` 排除自身。玩家领地发生重叠时，调整选区后再保存。

站到待检查位置执行 `/rg why block-break`，输出会显示结果、命中区域、规则来源、继承和成员豁免。管理员也可执行 `/rg why chest-access Alex`，按 Alex 当前的位置和权限查询。

同级区域的允许和禁止冲突时，禁止优先。管理员拥有绕过权限时可能得到允许，核对普通玩家效果应查询该玩家身份。

## 撤销一次设置

```text
/rg history 10
/rg diff 12
/rg undo 12
```

先用 `history` 找到需要撤销的操作编号，再用 `diff` 核对区域和设置内容，确认后执行 `undo`。

系统可查询最近 100 条在线操作，每次 `history` 最多查看 50 条。区域已被继续修改时，先核对后续操作再处理冲突。

撤销后也需满足父区关系和领地重叠限制。完成后用 `/rg info`、`/rg flags` 或面板核对结果。

## 导出与导入区域

```text
/rg export town_rules world
/rg import town_rules
/rg import town_rules apply <预检给出的校验码>
```

导出文件位于模块目录的 `region-backups/town_rules.yml`。复制到目标服务器的同名目录后执行预检，核对新增、相同内容、错误和重叠提示，再使用给出的校验码提交。

同名记录内容一致时跳过，内容冲突时需先处理。每份文件最多 4096 个区域或 4 MiB，可按世界拆分。文件名使用 1～64 位英文字母、数字、下划线或连字符，命令中省略 `.yml`。

## 排查保存与保护问题

| 现象或提示 | 核对方法 |
| --- | --- |
| 设置后尚未出现「已保存」 | 等待本次文件提交完成，再验证保护 |
| “regions.yml 已被手动修改” | 执行 `/axs reload regions`，重新打开面板再修改 |
| 保存失败 | 检查控制台的文件写入错误、目录权限和磁盘空间 |
| 区域规则没有按预期生效 | 核对世界、Y 高度、重叠区域、父区和玩家身份，用 `why` 查看来源 |
| 成员显示「未知玩家」 | 核对 UUID 所属账号及服务器是否保存其名称档案 |
| “Regions 聊天规则检查失败” | 检查服务端日志中的具体异常及聊天插件接入情况 |

## 在地图上核对边界

同时启用 Regions 和 Map 后，有 `axs.regions.admin` 的玩家可在 Map 大地图查看浏览世界的区域轮廓。管理区域显示紫色，玩家领地显示绿色。地图绘制水平范围，保护高度以区域数据和 `/rg info` 为准。

每个本地世界最多显示 256 个轮廓，查看自己所在世界时优先显示附近区域。游戏内的粒子预览使用 `/rg show`，用法见[粒子与附近边框](/docs/regions/selection#粒子与附近边框)。
