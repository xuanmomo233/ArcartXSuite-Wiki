---
title: "离线模式与游戏内密码"
description: "离线服玩家通过服务器 IP 或域名进服，首次在游戏内注册，之后在游戏内输入密码登录。"
---

离线模式指游戏服设置 `online-mode=false`。玩家用自己的游戏名连接服务器，在 LoginView 里注册本服账号、输入自己的密码登录，流程与 AuthMe 的游戏内注册和登录类似。玩家无需微软、LittleSkin 或其他外部账号，服主也无需给每个人预设密码。

## 设置离线直连

1. 在游戏服[启用 LoginView](/docs/loginview/getting-started#启用-loginview)。停服后，在游戏服根目录的 `server.properties` 将在线模式改为以下值。

   ```properties
   online-mode=false
   ```

2. `server-ip` 沿用服务器正常的监听配置，通常留空。玩家从自己的电脑连接服主提供的服务器 IP 或域名和游戏端口。直连游戏服按[所用核心的配置](/docs/loginview/getting-started#直连服的转发设置)关闭代理转发。
3. 默认的 `plugins/ArcartX-Suite/authentication.yml` 使用 `backend: standalone` 和 `ingress.type: auto`，离线直连时会自动启用游戏内登录。已有服也可显式选择 `ingress.type: password`。如果之前为其他入口写过 `ingress.password-login: false`，移除该项以恢复入口默认值。重启游戏服，在控制台用 `axs status` 确认 LoginView 已启用。

远程玩家的密码验证由 Suite 本体处理。仍提示「仅支持本机直连」的旧本体需要更新到支持远程离线登录的构建。

## 只要求游戏内密码

如果玩家登录后就应开始游戏，在 `authentication.yml` 中将以下两项设为 `false`。服规确认和 QQ 绑定是服主可选的[额外准入要求](/docs/loginview/configuration#准入要求)。

```yaml
requirements:
  terms: false
  qq-binding: false
```

每位玩家在首次进服时自己设置密码。服主需要调整长度、连续输错次数或冷却时间时，才修改 `password` 段的策略。默认接受 8 至 128 个字符，连续输错 5 次后冷却 300 秒。

## 注册与重新登录

1. 从另一台电脑使用新的游戏名连接服务器。注册界面输入个人密码，再输一次确认。提交前玩家应受到限制，注册成功并完成已开启的要求后应能移动和交互。
2. 断开后用同一个游戏名重新连接。这次应出现登录界面。输错一次，确认仍不能操作。再输入正确密码，确认可以游戏。
3. 服主可在游戏服控制台执行 `axs loginview account Alex`，将 `Alex` 换成在线玩家名。成功登录后应看到 `身份来源 local-password`、`身份验证 已通过` 和 `游戏准入 已放行`。[账号查询](/docs/loginview/commands#认证状态查询)
4. 要改密码时，管理员为这名已登录的玩家打开[账号管理界面](/docs/loginview/commands#账号管理界面)。玩家填写旧密码和新密码，之后用新密码重新登录。
