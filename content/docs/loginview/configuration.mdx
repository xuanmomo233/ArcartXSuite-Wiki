---
title: "准入要求与登录界面"
description: "让已验证身份的玩家确认指定版本的服规、完成 QQ 绑定，并调整登录界面的打开时间和外观。"
---

先用一个普通账号跑通所选登录方式，再逐项开启服务器要求。身份验证完成时，玩家可以继续处理条款和绑定。所有必需项完成后，Suite 才会放行。

## 准入要求

先看游戏服 `plugins/ArcartX-Suite/authentication.yml` 的 `backend`，据此确定在哪里改策略。

| 这台服的后端 | 条款与版本 | QQ 绑定 | 完成时限 |
| --- | --- | --- | --- |
| `standalone` | 游戏服的 `requirements.terms`、`terms.version` 和 `terms.lines` | `requirements.qq-binding` | `login-timeout-seconds` |
| `center` | `center.json` 对应 Realm 的 `requireTerms`、`termsVersion` 和 `termsLines` | 同一 Realm 的 `requireBinding` | 同一 Realm 的 `loginTimeoutSeconds` |

### 要求阅读服规

单服或代理子服使用 `standalone` 时，在已有 `authentication.yml` 中合并以下片段。保留已验证可用的 `ingress`。`version` 使用字符串，正文写 1 至 3 行，每行最多 60 个字符。

```yaml
requirements:
  terms: true
  qq-binding: false
terms:
  version: "1"
  lines:
    - "请尊重其他玩家，禁止破坏他人的建筑。"
login-timeout-seconds: 300
```

中心节点按[中心配置示例](/docs/loginview/center#编写中心配置)改对应 Realm。策略在哪个进程修改，就重启哪个进程。两种后端的完成时限均可设为 30 至 1800 秒。

验收时，用尚未同意当前版本的玩家登录。游戏内密码界面可以勾选条款后一起提交。进入单独的条款步骤时，勾选后点击「确认条款并继续」。下次以同一账号进服，已同意的版本应直接通过。修改服规后同步更换版本号，原账号再次进入时应收到新的条款。

### QQ 绑定要求

1. 先启用 QQBot 并确认机器人已连入目标群。用已建立游戏身份的测试账号走通一次[QQBot 账号绑定](/docs/qqbot/binding-whitelist#绑定)。
2. 启用上表中对应的绑定要求。中心模式在需要查询和发起绑定的节点 `nodes[].scopes` 保留 `auth`，并加入 `binding-read` 和 `binding-write`。重启修改了策略的进程。
3. 使用另一名未绑定的玩家验证身份。玩家在群中发送 `#绑定 游戏名`，将返回的验证码填入游戏界面的绑定栏，点「确认绑定」。验证码有效期为 300 秒，过期后在群中重新申请。
4. 完成其余要求后应能正常游戏。再次进服时，已有绑定的账号应直接通过绑定检查。

## 界面配置

打开延迟位于 `plugins/ArcartX-Suite/data/loginview/config.yml`，完整配置如下。

```yaml
config-version: 1
open-delay-ticks: 20
```

`open-delay-ticks` 的取值为 0 至 600 tick，默认 20 tick。Suite 3.3.7 会在 LoginView 启动或重载时重新导出 `plugins/ArcartX-Suite/ui/loginview/auth.yml`，界面 ID 是 `AXS:auth`。排查界面加载时可检查该文件和服务端的注册日志。

修改打开延迟后，在游戏服控制台执行 `axs reload loginview`。用仍有待完成要求的测试账号进服查看变化。已经放行且无需操作的玩家会正常进入游戏。
