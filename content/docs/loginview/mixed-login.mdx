---
title: "单服与代理混合登录"
description: "配置微软和 LittleSkin 的混合账号认证，支持单服直连、Velocity 和 BungeeCord，也可接入中心账号。"
---

混合网关在 Minecraft 在线握手时识别账号来源。看玩家在多人游戏列表里填的是哪个地址。填游戏服地址，配置下方单服路线。填代理地址，只在代理上运行网关，由每个子服校验代理转发的身份。

## 单服混合认证

### 生成启动脚本

1. 在游戏服的 `plugins/ArcartX-Suite/config.yml` 找到已有的 `auth` 段，设置以下字段。示例端口 `25599` 要在本机空闲，认证源末尾保留 `?mixed`。

   ```yaml
   auth:
     enabled: true
     yggdrasil-source: "https://littleskin.cn/api/yggdrasil?mixed"
     mixed-proxy-host: "127.0.0.1"
     mixed-proxy-port: 25599
   ```

2. 启动游戏服，在控制台执行 `axs auth setup`。看到根目录生成 `start-mixed-auth.bat` 和 `start-mixed-auth.sh` 后停服。这一步只需要 Suite 的认证工具。游戏内执行该命令需要 `arcartxsuite.admin` 和 `arcartxsuite.auth.admin`。

### 配置游戏服入口

在 `server.properties` 设置 `online-mode=true`，按[直连服的转发设置](/docs/loginview/getting-started#直连服的转发设置)关闭当前核心的玩家信息转发。对于没有 Mojang 聊天签名密钥的档案，在支持该设置的服务端将 `enforce-secure-profile=false`。启用 LoginView，在 `plugins/ArcartX-Suite/authentication.yml` 写入下例。示例中的网关端口与上一步一致，已有服保留自己的 `realm-id`。

```yaml
schema-version: 1
backend: standalone
realm-id: local
ingress:
  type: local-mixed
  gateway-url: http://127.0.0.1:25599
requirements:
  terms: false
  qq-binding: false
```

Windows 运行 `.\start-mixed-auth.bat`，Linux 运行 `bash ./start-mixed-auth.sh`。脚本先启动网关，再带着指向该网关的 `-javaagent` 参数启动游戏服。接到面板前，检查脚本里的 Java、游戏服 JAR 和内存参数，按原来的开服设置调整，并保留网关启动命令和 `-javaagent`。面板的实际启动命令应运行此脚本。然后[验证账号来源](#验证身份与准入)。

## 代理转发认证

以下示例把子服在代理里的注册名设为 `lobby`。玩家连接代理地址，子服的游戏端口只允许代理访问。

### 配置玩家信息转发

先把 `lobby` 登记在代理的服务器列表中。Velocity 使用 `velocity.toml` 的 `[servers]`，BungeeCord 使用代理 `config.yml` 的 `servers`。子服的 `server.properties` 均设为 `online-mode=false`，由代理完成在线验证。

| 代理和子服 | 代理上的设置 | 子服上的设置 |
| --- | --- | --- |
| Velocity → 原生 Spigot | 在 `velocity.toml` 设 `online-mode = true`、`player-info-forwarding-mode = "legacy"` | 在 `spigot.yml` 设 `settings.bungeecord: true`，接收 BungeeCord 格式的玩家信息 |
| Velocity → 使用原生 modern 转发的 Paper 系子服 | 在 `velocity.toml` 设 `online-mode = true`、`player-info-forwarding-mode = "modern"` | 在 `spigot.yml` 设 `settings.bungeecord: false`。在 `config/paper-global.yml` 开启 `proxies.velocity.enabled` 和 `proxies.velocity.online-mode`，将 `proxies.velocity.secret` 设为代理转发密钥文件的内容 |
| BungeeCord → Spigot 或 Paper 系子服 | 在代理 `config.yml` 设 `online_mode: true`、`ip_forward: true` | 在 `spigot.yml` 设 `settings.bungeecord: true`。采用 Paper 配置的子服还要开启 `proxies.bungee-cord.online-mode`、关闭 `proxies.velocity.enabled` |

同一台 Velocity 的转发模式对所有子服生效。混用核心时，选择每台子服都能接收的模式。其他兼容核心或第三方转发插件使用其自身的配置入口。使用 BungeeCord 格式转发时，通过监听地址或防火墙将子服游戏端口限制为仅代理可达。[Velocity 玩家信息转发](https://docs.papermc.io/velocity/player-information-forwarding/) · [Paper 代理设置](https://docs.papermc.io/paper/reference/global-configuration/#proxies)

接纳没有 Mojang 聊天签名公钥的档案时，在提供该选项的版本中，Velocity 设 `force-key-authentication = false`，BungeeCord 设 `enforce_secure_profile: false`。两端仍按上表执行在线握手和玩家信息转发。[Velocity 代理选项](https://docs.papermc.io/velocity/configuration/) · [BungeeCord 代理配置](https://github.com/SpigotMC/BungeeCord/blob/master/proxy/src/main/java/net/md_5/bungee/conf/Configuration.java)

### 生成代理启动脚本

安装与代理平台对应的 Suite 代理插件。在它生成的 `proxy-config.yml` 中调整下面的字段。第一次启动时先关闭 `auth-forwarding`，以便用代理控制台生成混合启动脚本。

```yaml
deny-offline: true
auth-forwarding:
  enabled: false
auth:
  enabled: true
  yggdrasil-source: "https://littleskin.cn/api/yggdrasil?mixed"
  mixed-proxy-bind-host: "127.0.0.1"
  mixed-proxy-port: 25599
```

启动代理，在代理控制台执行 `axsproxy auth setup`。生成脚本后停止代理。两种代理的游戏内管理权限都是 `arcartxsuite.proxy.admin`。

### 启用认证转发

用下面的内容替换同一份 `proxy-config.yml` 中的 `auth-forwarding` 段。`targets` 下每个键使用代理里已登记的子服名称。

```yaml
auth-forwarding:
  enabled: true
  issuer: proxy-main
  gateway-url: http://127.0.0.1:25599
  targets:
    lobby:
      realm: network
      audience: lobby-node
```

核对生成的脚本里使用的 Java、代理 JAR 和内存参数。在代理目录运行 `.\start-mixed-auth.bat` 或 `bash ./start-mixed-auth.sh`。从代理的 `[AuthForwarding]` 启动日志复制 `public-key=` 后的完整公钥。Velocity 的玩家信息转发密钥和这把 Suite 公钥分别填在各自的配置位置。

### 配置子服信任项

在 `lobby` 子服启用 LoginView，子服的 Suite `config.yml` 保持 `auth.enabled: false`。把下例写入子服的 `plugins/ArcartX-Suite/authentication.yml`，替换公钥后重启子服。

```yaml
schema-version: 1
backend: standalone
realm-id: network
ingress:
  type: signed-proxy
  audience: lobby-node
  trusted-proxies:
    - issuer: proxy-main
      public-key: "替换为代理日志中的完整公钥"
      providers: [microsoft, littleskin]
requirements:
  terms: false
  qq-binding: false
```

逐项对齐两端。`targets.lobby.realm` 对应子服的 `realm-id`，`targets.lobby.audience` 对应 `ingress.audience`，代理的 `issuer` 对应信任列表中的 `issuer`。添加另一台子服时，在 `targets` 增加该服的注册名，并按它的目标标识填写对应的子服配置。

## 加入 Suite AuthCenter

当玩家要用官网账号**启动游戏**时，在现有混合网关增加这个来源。

1. 按[认证中心教程](/docs/loginview/center#获取认证中心)部署中心并[登记启动器](/docs/loginview/center#登记启动器)。开启 `external.minecraftSessions`，让中心的 `/v1/external/` 路径可通过 HTTPS 访问。
2. 在**启动网关的进程**中设置 `AXS_MIXED_CENTER_ORIGIN`。填中心的 HTTPS 根地址，省略末尾斜线、路径和查询串。下例在 Windows 的游戏服目录或代理目录运行。

   ```powershell
   $env:AXS_MIXED_CENTER_ORIGIN = 'https://auth.example.net'
   & .\start-mixed-auth.bat
   ```

   Linux 使用 `AXS_MIXED_CENTER_ORIGIN=https://auth.example.net bash ./start-mixed-auth.sh`。用面板或系统服务管理进程时，把这个变量设置在实际运行脚本的服务环境里。

3. 单服沿用 `backend: standalone` 和 `ingress.type: local-mixed`。代理子服沿用 `backend: standalone` 和 `ingress.type: signed-proxy`，在每个接收中心账号的子服将 `trusted-proxies[].providers` 改为 `[microsoft, littleskin, center]` 并重启。混合入口的条款和绑定由游戏服的 `authentication.yml` 配置。
4. 启动器经官网授权，按[兑换 Minecraft 会话](/docs/loginview/external-api#兑换-minecraft-会话)取得中心档案，使用返回的档案和凭据启动客户端。中心为账号分配独立的 `AXS_` 档案，进服后可查到来源 `center`。

### 加入独立认证服务

自有 Yggdrasil 服务提供 HTTPS `hasJoined` 时，让客户端先用该服务登录，在网关进程把 `AXS_MIXED_CENTER_HAS_JOINED` 设为它完整的 `hasJoined` 接口地址，省略查询串和片段。此变量与 `AXS_MIXED_CENTER_ORIGIN` 二选一，重启网关生效。通过代理接入时，子服也要允许来源 `center`。

## 验证身份与准入

分别使用微软、LittleSkin 和实际启用的中心账号，经玩家平时使用的地址进服。可在[认证状态查询](/docs/loginview/commands#认证状态查询)核对来源，预期依次为 `microsoft`、`littleskin`、`center`。示例关闭了条款与绑定，握手完成即可游戏。新增要求后，使用未完成要求的账号复测。

单服一直等待验证时，先检查实际启动命令和网关端口。代理服则先看玩家是否连到代理、`lobby` 是否注册正确，再核对子服的 Realm、目标标识、签发者、公钥及允许的来源。中心账号的会话用于一次连接，掉线后由启动器重新授权和兑换。
