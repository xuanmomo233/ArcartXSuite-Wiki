---
title: "混合账号认证"
description: "在同一套混合登录中验证微软、LittleSkin 和 Suite AuthCenter 账号，支持单服直连和可信代理转发。"
---

混合网关默认验证微软与 LittleSkin。启用 Suite AuthCenter 会话后，中心账号通过启动器完成授权，就可以直接进入同一台服务器。身份验证完成后，玩家继续完成游戏服要求的条款与 QQ 绑定。

| 连接拓扑 | 认证入口 | 网关部署位置 |
| --- | --- | --- |
| 玩家直接连接游戏服 | 单服混合认证，`local-mixed` | 与游戏服同一台机器 |
| 玩家通过 BungeeCord 或 Velocity 进入子服 | 代理转发认证，`signed-proxy` | 与代理同一台机器 |

通过混合网关验证的玩家免输本服密码。本机断网测试使用独立的[本机离线密码入口](/docs/loginview/configuration)，不使用混合网关。

## 单服混合认证

### 生成启动脚本

游戏服需要安装 Suite 和 LoginView。在宿主 `config.yml` 中设置以下 `auth` 配置，保留文件里的其他设置。

```yaml
auth:
  enabled: true
  auto-check-version: false
  yggdrasil-source: "https://littleskin.cn/api/yggdrasil?mixed"
  mixed-proxy-port: 25599
  mixed-proxy-host: "127.0.0.1"
  mixed-proxy-token: ""
```

设置 `auth.enabled: true` 后重启游戏服，在控制台执行 `axs auth setup`。游戏内执行 `/axs auth setup` 同时需要 `arcartxsuite.admin` 和 `arcartxsuite.auth.admin`。

确认服务器根目录生成 `start-mixed-auth.bat` 和 `start-mixed-auth.sh`，然后停服。脚本会先启动本机网关，再带着所需的认证参数启动游戏服。

### 配置游戏服入口

在 `server.properties` 中设置 `online-mode=true`。

将以下完整内容保存到游戏服的 `plugins/ArcartX-Suite/authentication.yml`。

```yaml
schema-version: 1
backend: standalone
realm-id: local
timezone: Asia/Shanghai
login-timeout-seconds: 300
ingress:
  type: local-mixed
  gateway-url: http://127.0.0.1:25599
  password-login: false
requirements:
  terms: true
  qq-binding: false
terms:
  version: '1'
  lines:
    - '请遵守服务器规则，保护账号凭据。'
performance:
  workers: 2
  queue-capacity: 128
```

`gateway-url` 的端口必须与上一步的 `mixed-proxy-port` 一致，地址使用本机 `127.0.0.1`。

### 启动游戏服

Windows 使用 `start-mixed-auth.bat`，Linux 使用 `start-mixed-auth.sh`。主机面板需要实际执行对应脚本，或完整保留脚本里的启动顺序和 Java 启动参数。

认证入口同时检查网关和实际 Java 启动参数，游戏服须通过生成的混合启动脚本启动。

### 加入 Suite AuthCenter

1. 按[外部授权配置](/docs/loginview/external-authorization#外部授权配置)部署中心并登记启动器，在 `center.json` 的 `external` 段设置 `minecraftSessions: true`。公网 HTTPS 继续将 `/v1/external/` 转发到中心的外部授权端口。
2. 游戏服保持 `online-mode=true` 和 `local-mixed`。使用中心档案时，将直接游戏服的 `enforce-secure-profile` 设为 `false`，允许不带 Mojang 聊天签名密钥的中心档案连接。在线握手仍由混合网关验证。
3. 在启动混合网关的环境中设置中心的 HTTPS 根地址。不要在地址后附带 `/v1/external` 或接口路径。

   ```powershell
   $env:AXS_MIXED_CENTER_ORIGIN = 'https://auth.example.net'
   & .\start-mixed-auth.bat
   ```

4. 启动器完成中心的浏览器或设备授权，按[启动器接口](/docs/loginview/external-api#兑换-minecraft-会话)兑换 Minecraft 会话。用返回的档案、凭据和会话地址启动客户端，即可进服，无需先选择微软或 LittleSkin 账号。

网关对中心分配的 `AXS_…` 档案先查询 AuthCenter，会话通过后由 LoginView 识别为 `center`。微软和 LittleSkin 玩家仍使用各自的登录方式。中心档案的名称和 UUID 由中心分配并持久保存，与其他来源的档案分开。

如果在代理端运行混合网关，在代理启动环境设置同一个变量，并将 `center` 加到子服相应的 `trusted-proxies[].providers` 列表。代理维持在线验证。

### 加入独立认证服务

也可接入其他提供 Yggdrasil HTTPS `hasJoined` 的独立服务。客户端使用对应服务登录。下列变量填写完整接口地址，且不能与 `AXS_MIXED_CENTER_ORIGIN` 同时设置。

```powershell
$env:AXS_MIXED_CENTER_HAS_JOINED = 'https://identity.example.net/sessionserver/session/minecraft/hasJoined'
& .\start-mixed-auth.bat
```

替换示例域名和路径。混合网关将此入口标记为 `center`。它按当前在线握手核验身份。公开资料查询地址和单纯的网页登录地址不能用作该接口。

在代理端接入该服务时，在代理启动环境设置变量，并将 `center` 加到子服对应的 `trusted-proxies[].providers` 列表。

### 验证身份与准入

分别用微软、LittleSkin 和中心启动器账号验证登录。通过后，玩家应进入条款步骤或直接进入游戏。中心会话凭据只能用于一次连接；握手过期或已消费时，在启动器重新授权和兑换。

## 代理转发认证

BungeeCord 或 Velocity 验证玩家身份，子服校验代理传入的认证结果。

### 配置玩家信息转发

在代理的 `servers` 中登记子服。下文使用子服名称 `lobby`。两种代理的子服都在 `server.properties` 中设置 `online-mode=false`，并在网络上限制只有代理可以连接子服。

- **Velocity** 在 `velocity.toml` 中设置 `online-mode=true` 和 `player-info-forwarding-mode="modern"`。Paper 子服在 `config/paper-global.yml` 中开启 `proxies.velocity.enabled`，设置 `proxies.velocity.online-mode: true`，并使 `proxies.velocity.secret` 与代理一致。子服的 `spigot.yml` 使用 `settings.bungeecord: false`。 [Velocity 转发说明](https://docs.papermc.io/velocity/player-information-forwarding/#configuring-modern-forwarding-for-paper)
- **BungeeCord** 在代理自己的 `config.yml` 中设置 `online_mode: true` 和 `ip_forward: true`。子服的 `spigot.yml` 使用 `settings.bungeecord: true`。Paper 子服还需在 `config/paper-global.yml` 中设置 `proxies.bungee-cord.online-mode: true`，并关闭 `proxies.velocity.enabled`。[Paper 代理配置](https://docs.papermc.io/paper/reference/global-configuration/#proxies)

### 生成代理启动脚本

安装与代理类型对应的 Suite 代理端插件。编辑插件生成的 `proxy-config.yml`，先配置以下内容。

```yaml
deny-offline: true
auth-forwarding:
  enabled: false
auth:
  enabled: true
  auto-check-version: false
  yggdrasil-source: "https://littleskin.cn/api/yggdrasil?mixed"
  mixed-proxy-port: 25599
  mixed-proxy-bind-host: "127.0.0.1"
  mixed-proxy-token: ""
  mixed-proxy-allow-ips: []
```

启动一次代理，在代理控制台执行 `axsproxy auth setup`。生成脚本后停止代理。后续使用代理目录里的 `start-mixed-auth` 脚本启动，保持代理的在线模式开启。

### 启用认证转发

将代理 `proxy-config.yml` 中的 `auth-forwarding` 整段替换为以下内容，再用新脚本启动代理。

```yaml
auth-forwarding:
  enabled: true
  issuer: proxy-main
  gateway-url: http://127.0.0.1:25599
  targets:
    lobby:
      realm: network
      audience: lobby-node
```

在代理启动日志中找到以 `[AuthForwarding]` 开头、包含 `public-key=` 的一行。复制其中完整的公钥值，下一步填到子服。代理生成的私钥文件留在代理端。

### 配置子服信任项

子服安装 Suite 和 LoginView。将下面完整配置保存到子服的 `plugins/ArcartX-Suite/authentication.yml`，把公钥占位符换成刚复制的值。

```yaml
schema-version: 1
backend: standalone
realm-id: network
timezone: Asia/Shanghai
login-timeout-seconds: 300
ingress:
  type: signed-proxy
  audience: lobby-node
  password-login: false
  trusted-proxies:
    - issuer: proxy-main
      public-key: "替换为代理日志中的完整公钥"
      providers: [microsoft, littleskin]
requirements:
  terms: true
  qq-binding: false
terms:
  version: '1'
  lines:
    - '请遵守服务器规则，保护账号凭据。'
performance:
  workers: 2
  queue-capacity: 128
```

子服的宿主 `config.yml` 中 `auth.enabled` 保持 `false`，混合网关由代理启动。开启子服的 LoginView，然后重启子服。

| 代理上的字段 | 子服上要对应的字段 | 本例 |
| --- | --- | --- |
| `targets` 下的子服名称 | 代理上的子服注册名称 | `lobby` |
| `targets.lobby.realm` | `realm-id` | `network` |
| `targets.lobby.audience` | `ingress.audience` | `lobby-node` |
| `issuer` | `trusted-proxies` 中的 `issuer` | `proxy-main` |
| 启动日志的 `public-key` | `trusted-proxies` 中的 `public-key` | 复制完整公钥 |

### 验证代理入口

玩家通过代理地址进入。分别用微软和 LittleSkin 账号连接，子服应接受验证结果并继续条款步骤。

若一直等待可信验证，先核对上表五项，再检查实际连接是否来自已配置的 `lobby` 子服及其转发设置。

代理连接连续超过 12 小时后，若切服时身份验证未通过，请断开代理并重新连接，再进入子服。

## 部署约束

| 配置情况 | 处理要求 |
| --- | --- |
| 玩家通过代理进入，而子服配置了 `local-mixed` | 将子服认证入口设为 `signed-proxy`，把网关部署在代理端 |
| 单服提示需要在线模式 | 单服混合认证的游戏服必须设置 `online-mode=true` |
| 在中心模式中使用混合入口 | 中心节点按独立中心教程配置，当前中心入口要求直连 |
| 只在本机做离线测试 | 使用回环监听的 `password` 入口，游戏服保持 `online-mode=false` |

本机游戏内密码的部署步骤见[本机离线密码](/docs/loginview/configuration)。
