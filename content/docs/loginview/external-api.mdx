本页供启动器开发者使用。先让服主在中心[登记启动器](/docs/loginview/center#登记启动器)，取得公开 HTTPS 根地址、启动器 ID 和登记的回环回调地址。官网的 OIDC 应用密钥由中心持有。

调用分两步。先选浏览器授权或设备授权，拿到一次性 `launchToken`。然后根据玩家此刻的目标，用它**兑换 Minecraft 会话**或**配对已经连上的游戏**。

## 通用请求格式

全部接口使用 `POST`，发送 UTF-8 JSON，请求头为 `Content-Type: application/json`。每次调用都包含数字 `version: 1`、新生成的 UUID 字符串 `requestId` 和已登记的 `clientId`。下表及后文列出的业务字段加在同一层。

中心响应含 `version`、本次 `requestId` 和 `code`。`value` 有值时类型为字符串。浏览器地址、启动凭据和配对核对码直接读取。设备挑战、轮询结果和 Minecraft 会话需要将 `value` 再解析一次 JSON。

## 浏览器授权流程

1. 启动器在登记的回环地址监听回调。本次分别用 32 字节安全随机数生成 `state` 和 `codeVerifier`，编码为无填充 Base64url。对 verifier 的 ASCII 字节作 SHA-256，再用同样编码得到 `codeChallenge`。
2. 请求 `/v1/external/launcher/start`，在通用字段外提交 `redirectUri`、`codeChallenge`、`state`。成功时用系统浏览器打开 `value` 中的中心授权地址。玩家在官网完成登录、确认，并返回启动器。
3. 校验回调的协议、主机、端口、路径和本次 `state`。若参数为 `error=access_denied`，结束本次操作。若返回 `code`，请求 `/v1/external/launcher/exchange`，提交 `redirectUri`、`code`、原始 `codeVerifier`。成功响应的 `value` 是 120 秒有效的启动凭据。

Java 接入可使用 `auth-protocol` 的 `xuanmo.arcartxsuite.auth.protocol.LauncherAuthorizationClient`。构造函数接收中心根地址（`URI`）、已登记的启动器 ID（`String`）及回调地址（`URI`）。调用 `start()`，打开返回对象的 `authorizationUrl()`。收到回调后调用 `exchange(attempt, callbackUri)`，返回启动凭据字符串。回环监听与打开浏览器由启动器实现。

## 设备授权流程

适合让玩家在另一台设备上完成官网登录。以下 PowerShell 7 示例从已部署的中心申请一组真实设备码。将根地址与启动器 ID 换为自己的登记值。

```powershell
$origin = 'https://auth.example.net'
$clientId = 'example-launcher'
$body = @{
  version = 1
  requestId = [guid]::NewGuid().ToString()
  clientId = $clientId
} | ConvertTo-Json -Compress
$reply = Invoke-RestMethod -Method Post -Uri "$origin/v1/external/launcher/device/start" -ContentType 'application/json' -Body $body
$device = $reply.value | ConvertFrom-Json
$device | Select-Object verificationUrl, userCode, expiresIn, interval
```

玩家打开 `verificationUrl`，输入公开的 `userCode` 并授权。启动器自己保留 `deviceCode`。当前挑战有效 300 秒，初始轮询间隔为 5 秒，实际调度读取返回的 `expiresIn` 和 `interval`。

### 轮询与取消

等待 `interval` 秒后请求 `/v1/external/launcher/device/poll`。在通用字段外提交 `deviceCode`。先读外层 `code`，再解析 `value` 中的 `code`、`interval`、`launchToken`。

| 轮询结果 | 启动器下一步 |
| --- | --- |
| `AUTHORIZATION_PENDING` | 玩家仍在处理，等待返回的间隔再轮询 |
| `SLOW_DOWN` | 把间隔改为新返回的秒数，再等待和轮询 |
| `ACCESS_DENIED` 或 `EXPIRED_TOKEN` | 停止轮询，玩家可重新发起 |
| `OK` | 停止轮询，读取 `launchToken` 并继续下面一个操作 |

玩家从启动器取消时，请求 `/v1/external/launcher/device/cancel`，字段与轮询相同，成功返回 `OK`。Java 封装对应 `startDevice()`、`pollDevice(attempt)` 和 `cancelDevice(attempt)`。

## 兑换 Minecraft 会话

用于玩家**尚未启动游戏**并希望使用中心档案进服的情形。中心开启 `external.minecraftSessions`，服务器接入[中心混合登录](/docs/loginview/mixed-login#加入-suite-authcenter)。

请求 `/v1/external/launcher/minecraft-session`，在通用字段外提交 `launchToken`。成功后解析 `value`，也可用 Java 方法 `minecraftSession(launchToken)` 直接取得会话对象。

| 返回字段 | 如何启动游戏 |
| --- | --- |
| `sessionApi` | 客户端 JVM 参数使用 `-javaagent:<authlib-injector 路径>=<sessionApi>` |
| `profileId`、`name` | 分别作为 Minecraft 的 `--uuid`（无连字符）和 `--username` |
| `accessToken` | 用作本次游戏档案的 `--accessToken`，启动日志应隐藏该值 |
| `expiresIn` | 本次凭据的有效秒数，当前为 300 |

使用同一响应的档案和凭据启动客户端，连接启用该来源的混合入口，预期玩家身份来源为 `center`。该凭据仅供一次成功连接，过期或已使用时重新授权兑换。

## 游戏连接配对

用于玩家**已经加入中心游戏节点**并看到 LoginView 授权码的情形。让玩家将游戏显示的码输入启动器。请求 `/v1/external/launcher/pair`，在通用字段外提交 `launchToken` 和 `userCode`。这里的 `userCode` 取自本次游戏连接，设备授权页另有自己的用户码。

成功的 `value` 是 8 位十六进制核对码。启动器展示它，玩家回到原连接点击「刷新状态」，核对相同后确认授权。Java 调用为 `pair(launchToken, userCode)`。每个启动凭据仅能消费一次，兑换会话与游戏配对各自需要新凭据。

## 错误处理

| HTTP 或响应码 | 处理 |
| --- | --- |
| `400 UNSUPPORTED_VERSION` | 核对 `version` 是数字 `1` |
| `400 AUTHORIZATION_REJECTED` | 核对该接口的字段、登记的回调和本次凭据。授权已失效时重新发起 |
| `429` | 按响应头 `Retry-After` 等待。Java 客户端的 `RateLimitedException.retryAfterSeconds()` 提供等待秒数 |
| `503 UNAVAILABLE` | 检查中心和身份提供方的服务状态，恢复后重新发起授权 |

接入验收至少走通一次授权成功和一次玩家拒绝。成功时检查实际游戏结果，拒绝或取消时启动器应停止等待。中心进程重启后，未完成的临时授权需要重新发起。
