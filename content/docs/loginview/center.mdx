想让 Suite AuthCenter 账号和微软、LittleSkin 一起通过 Minecraft 握手，使用[混合登录](/docs/loginview/mixed-login#加入-suite-authcenter)。玩家通过中心授权后，即可用启动器启动游戏进服。

本页其余内容介绍进服后由中心管理准入的模式。玩家先完成 Minecraft 在线握手，再在 LoginView 确认中心网页或启动器授权。两种模式均无需在游戏内输入本服密码。

## 部署条件

| 准备项 | 要求 |
| --- | --- |
| 独立中心发行包 | 使用 Java 17 或更高版本，解压后有 `bin` 和 `lib` 目录 |
| 游戏服 | 安装 Suite 和 LoginView，玩家直连，`online-mode=true`，关闭 BungeeCord、Velocity 转发 |
| 身份来源 | 有可用的 OIDC 身份提供方；使用启动器时也须在中心登记启动器 |
| 节点密钥 | 中心与对应游戏服使用同一个密钥，各自在运行环境中设置 |

本页使用的 `backend: center` 与 `ingress.type: external` 用于进服后的授权确认。只用中心账号完成 Minecraft 握手时，游戏服使用混合入口，并由启动器在启动游戏前兑换会话。

## 启动中心

1. 在 PowerShell 7 生成节点密钥。每个游戏节点使用不同的值。

   ```powershell
   [Convert]::ToBase64String([Security.Cryptography.RandomNumberGenerator]::GetBytes(32))
   ```

2. 按[外部授权配置](/docs/loginview/external-authorization#外部授权配置)填写完整的 `center.json`，配置 OIDC 提供方和公开 HTTPS 地址。Realm 使用 `gamePasswordEnabled: false`。
3. 在中心进程中设置节点密钥和 OIDC 应用密钥，再启动中心。下例的启动脚本与配置文件位于 `D:/AXSAuth/`。

   ```powershell
   $env:AXS_AUTH_LOBBY_KEY = '粘贴生成的节点密钥'
   $env:AXS_WEBSITE_OIDC_SECRET = '粘贴身份提供方分配的应用密钥'
   & 'D:\AXSAuth\bin\auth-center.bat' 'D:\AXSAuth\center.json'
   ```

样例使用 `127.0.0.1:25600` 接收节点请求，`127.0.0.1:25601` 接收外部授权转发。两个端口用途不同。环境变量只传给启动它们的进程；使用服务或面板时，在对应启动环境设置。

## 游戏节点配置

在游戏服的 `plugins/ArcartX-Suite/authentication.yml` 中填写：

```yaml
schema-version: 1
backend: center
realm-id: network
ingress:
  type: external
  audience: lobby-node
performance:
  workers: 2
  queue-capacity: 128
  renewal-workers: 2
  renewal-queue-capacity: 4096
center:
  url: http://127.0.0.1:25600
  node-id: lobby
  key-environment: AXS_AUTH_LOBBY_KEY
```

| 游戏服字段 | 中心字段 | 本例值 |
| --- | --- | --- |
| `realm-id` | `realms[].id`、`nodes[].realm` | `network` |
| `center.node-id` | `nodes[].id` | `lobby` |
| `ingress.audience` | `nodes[].audience` | `lobby-node` |
| `center.key-environment` | `nodes[].keyEnvironment` | `AXS_AUTH_LOBBY_KEY` |

`key-environment` 填变量名。游戏服进程中的变量值与该节点在中心的值相同；游戏服不需要 OIDC 应用密钥。异机游戏服使用 HTTPS 的 `center.url`，将 `/v1/node/rpc` 转发到中心节点端口，并保持机器时钟同步。

## 验证准入

执行 `axs status` 确认 LoginView 启用，再让测试玩家以在线账号直连。游戏应显示授权地址和当前连接的授权码。完成[浏览器或启动器授权](/docs/loginview/external-authorization)后，在原连接核对并确认。开启条款或 QQ 绑定时，完成相应步骤后才允许操作。

中心的节点或 Realm 配置改变后重启中心；游戏服的 `authentication.yml` 改动后重启游戏服。[界面设置](/docs/loginview/configuration#界面配置)可以单独重载。
