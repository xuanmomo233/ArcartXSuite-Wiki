## 获取接口

通过 `AxsCapabilities.get(EventBusCapability.class)` 获取接口，按[调用约定](/docs/api/quick-start#调用约定)处理不可用结果。

## 方法声明

```java
public interface EventBusCapability {

    void publish(@NotNull String topic, @Nullable Player player, @NotNull Object payload);

    void publish(@NotNull String topic, @Nullable Player player, @NotNull Map<String, String> payload);

    void registerPublisher(@NotNull String topic);

    boolean hasPublisher(@NotNull String topic);
    boolean hasSubscribers(@NotNull String topic);
    CompletionStage<Boolean> publishConfirmed(@NotNull String topic, @Nullable Player player,
                                              @NotNull Map<String, String> payload);
    String subscribeConfirmed(@NotNull String consumer, @NotNull String topic,
                              @NotNull ConfirmedHandler handler);

    String subscribe(@NotNull String topic, @NotNull EventHandler handler);

    void unsubscribe(@NotNull String subscriptionId);

    record BusEvent(
        @NotNull String topic,
        @Nullable Player player,
        @NotNull Object typedPayload,
        long timestamp
    ) {}

    interface ConfirmedHandler {
        CompletionStage<Void> handle(@NotNull BusEvent event);
    }

    @FunctionalInterface
    interface EventHandler {
        void handle(@NotNull BusEvent event);
    }
}
```

## 参数与返回值

| 方法 | 用途 | 参数 | 返回值 |
| --- | --- | --- | --- |
| `publish` | 发布一个事件到总线（类型安全版本）。 payload 可以是任意类型（如自定义 record、BigDecimal、ItemStack 等）， 订阅方通过 `BusEvent#typedPayload()` 获取并按需强制转换。 | `topic`：事件主题；`player`：关联玩家（可能为 null，如系统事件）；`payload`：附加数据（任意类型） | 无返回值 |
| `registerPublisher` | 注册当前模块为指定主题的发布者。 模块在 `onEnable` 时调用此方法声明自己会发布的事件主题， 以便其他模块在启动时通过 `#hasPublisher(String)` 检测是否可订阅。 重复注册同一主题是安全的（幂等）。 | `topic`：事件主题 | 无返回值 |
| `hasPublisher` | 查询指定主题是否已有注册的发布者。 用于在启动时判断某个 EventBus 主题是否有模块发布， 若无则可降级到其他事件源（如原版 Bukkit 事件）。 | `topic`：事件主题 | `true` 表示至少有一个模块已注册为该主题的发布者 |
| `hasSubscribers` | 检查普通订阅和回执订阅 | `topic` 为完整主题名 | 有匹配的订阅时为 `true`，通过回执接口判断业务是否已处理 |
| `publishConfirmed` | 发布受支持的回执事件 | 精确主题、可为空的玩家和含 `event_id` 的字符串映射 | 异步布尔值，失败为 `false`。不支持的主题或缺少事件 ID 会抛出 `IllegalArgumentException` |
| `subscribeConfirmed` | 按精确主题注册回执订阅 | 稳定消费者 ID、主题、异步处理器 | 可用 `unsubscribe` 注销的 ID。同一主题重复注册同一消费者会抛出 `IllegalStateException` |
| `subscribe` | 订阅一个事件主题。 | `topic`：事件主题（支持通配符 `"axs.market.*"`）；`handler`：处理器 | 订阅 ID（用于取消订阅） |
| `unsubscribe` | 取消订阅。 | `subscriptionId`：订阅 ID | 无返回值 |

## 调用注意事项

普通业务事件使用 `publish` 和 `subscribe`。回调按发布方的线程执行。用 `typedPayload()` 读取原始对象；只有在主题约定为字符串映射时才用 `payload()` 读取字段。停用插件时取消订阅。

回执订阅只接受 `axs.auth.profile_first_admitted`、`axs.auth.presence_day_started` 和 `axs.market.auction_purchased`。处理器按 `event_id` 去重，异步保存业务结果后再完成回执。认证主题没有回执订阅者时返回 `false`。

拍卖成交主题是 `axs.market.auction_purchased`。已配置的 BattlePass 或 EventPacket 订阅尚未就绪时，Market 保留待处理事件。订阅方应同时保存 `event_id` 和处理结果。收到已完成的事件时返回成功。付费客户水印版跨服运行同一订阅时须共享存储。

## 区域进出事件

Regions 使用 `axs.regions.region_change` 发布实际进入和离开。负载包含区域 UUID、世界、名称和移动原因，多次跨界按发生顺序通知订阅者。需要统计不同区域时，按自己的任务周期与区域 UUID 去重。字段和订阅示例见[区域保护判定接口](/docs/api/RegionProtectionQueryable#订阅实际进出事件)。
