## 开始前

在两台已[完成安装](/docs/guide/first-run)的游戏服启用 Announcer，下文以 `lobby` 和 `survival` 为例。配置跨服前确认两服各自能显示公告。

| 目的 | 应配置的内容 |
| --- | --- |
| 跨服公告和其他模块通知 | 选 Redis 或代理转发，然后打开目标模块的跨服开关 |
| 跨服聊天 | 各服使用同一个 MySQL 数据库，再开启 Chat 跨服与频道转发 |
| 多服访问同一个共享仓库 | 各服连接同一个 MySQL 库，并开启 Warehouse 的跨服编辑锁 |
| 跨服地图传送 | 完成消息连接后，继续配置[跨服地图](/docs/map/cross-server)的代理服名称和目标落地点 |

## 用 Redis 连接两台服

两台游戏服应连接同一个 Redis 实例和数据库。示例中的 `127.0.0.1` 适用于游戏服和 Redis 均在同一主机、同一网络环境的情况。分开部署时，在两台游戏服填写同一个可达的 Redis 内网地址。分别从游戏服所在环境用 `redis-cli` 连接并执行 `PING`，应返回 `PONG`。

在两台游戏服各自的 `plugins/ArcartX-Suite/config.yml` 中合并以下小节。大厅用 `node-id: "lobby"`，生存服改为 `node-id: "survival"`。两边使用相同的 Redis 地址、频道和共享密钥，密钥填写自建的随机值。

```yaml
cross-server:
  node-id: "lobby"
  redis:
    enabled: true
    host: "127.0.0.1"
    port: 6379
    username: ""
    password: ""
    database: 0
    channel: "AXS:CROSS:TEST"
  proxy:
    enabled: false
  signature:
    enabled: true
    secret: "替换为两服相同的随机密钥"
    verify: true
```

### Redis 连接要求

Redis 须为 6.2 或更高版本。同一频道的子服应使用相同的留存设置，每台子服须有独立的 `node-id`。使用 Redis ACL 用户时，填写 `cross-server.redis.username`。

分别检查所需模块的跨服开关。`cross-server.dedupe-ttl-ms` 同时限定接收方接受的消息年龄和去重时间窗口，默认 60 秒。验证跨服连接时，恢复通道后发一条新消息。

## 使用代理转发

已有 BungeeCord 或 Velocity 代理、两台游戏服都能通过该代理进入时，可以改走代理转发。在 Velocity 的 `velocity.toml` 中将 `[advanced]` 下的 `bungee-plugin-message-channel` 设为 `true`。配置位置见 [Velocity 配置参考](https://docs.papermc.io/velocity/configuration/)。

在上面的本体配置中保留各服独立的 `node-id` 和一致的 `signature` 设置，将连接方式改为以下值。修改后重启代理和两台游戏服。

```yaml
cross-server:
  redis:
    enabled: false
  proxy:
    enabled: true
    messenger-channel: "AXS_CROSS"
    forward-target: "ALL"
```

仅使用代理转发时，发送服须有在线玩家。验证时分别在发送服和接收服保留一名玩家。

调整跨服连接方式时，保留各服自己的 `node-id`，确认所需模块已启用新通道，并检查各服的签名配置。

## 按模块开启

在两台游戏服各自的 `plugins/ArcartX-Suite/data/announcer/config.yml` 中启用跨服公告。

```yaml
cross-server:
  enabled: true
```

Tab 的跨服名单通过 Suite Velocity 配置。 [跨服名单](/docs/tab/cross-server)

## 验证步骤

1. 重启两台游戏服。在各自控制台执行 `axs announcer status`，确认「跨服通道」为「已启用」。
2. 在大厅控制台执行 `axs announcer gbroadcastnow 双服验收：大厅发出`。大厅和生存服的在线测试玩家都应在公告 HUD 看到这段文字。
3. 在生存服控制台执行 `axs announcer broadcastnow 双服验收：仅生存服`。只应在生存服看到它。文件中的自动轮播也只在本服显示。
4. 远端未收到时，核对接收玩家是否在线、各服 `node-id` 是否不同、频道和密钥是否一致，以及接收服是否启用 Announcer。本服也无公告时，检查[本服轮播](/docs/announcer#第一次使用)。

## 验证共享仓库

1. 在两台服启用 Warehouse 和 PlaceholderAPI。在本体 `config.yml` 按[MySQL 配置](/docs/guide/first-run#使用-mysql)连接同一个数据库，填写能访问该库的账号。
2. 在两台服的 `data/warehouse/config.yml` 合并下例，再重启。`storage.shared` 让 Warehouse 使用本体的数据库，`cross-server.enabled` 打开跨服编辑锁。

```yaml
storage:
  shared: true
shared:
  enabled: true
cross-server:
  enabled: true
```

3. 核对 `shared.create-cost` 和玩家 A 的余额。使用默认配置时，启用 PlayerPoints，并为 A 准备 1,000 点券。随后在大厅用玩家 A 执行 `/warehouse open`，按[共享仓库操作](/docs/warehouse/shared-warehouse)创建仓库并把玩家 B 加为成员。
4. 玩家 A 存入 1 个铁锭并关闭仓库。玩家 B 到生存服打开同一仓库，应看到 1 个铁锭。随后让 A 在大厅打开编辑，B 在生存服重新打开同一仓库，应只能查看。A 关闭后，B 重新打开应能取出铁锭。
5. 看不到同一份内容时查数据库和成员身份。内容一致但两边都能编辑时，执行 `/axs warehouse status` 查看编辑锁是否启用，再查跨服连接。
